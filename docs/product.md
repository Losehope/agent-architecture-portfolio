# 产品文档

## 问题

面向业务用户的问答助手，问题类型差异大：有的要查一个基准数字，有的要一组关键词，有的是
知识库里的规则，有的是需要专家判断的策略。单一的“检索 + 大模型”方案在这些场景里有三类问题：
数字被改写错、敏感数据被带出、策略类问题要等很久。

## 用户与场景

- 一线运营：问行业基准（CPM、CTR）、要关键词建议、查售后规则。
- 策略同事：问预算怎么分配，需要专家 Agent 的意见。

## 核心能力

| 能力 | 用户看到的效果 |
|---|---|
| 查基准 | 直接给出表格，注明数据周期，不展示内部权重 |
| 术语清单 | 给出对应类目的术语清单；类目不明确时给出可选项，让用户点选 |
| 知识问答 | 先走轻型 RAG（向量 / BM25 / 关键词 + RRF），复杂问题升级重型 RAG（查询改写 + 重排 + 多跳）；回答给出规则原文，并列出来源文件 |
| 策略咨询 | 先收到受理回执和编号，稍后收到一条整合后的回复 |
| 安全兜底 | 触及不可披露的数据时给出固定的拒答，不给残缺答案 |

## 体验原则

1. 能立刻答的立刻答；不能立刻答的先给回执，不让用户空等。
2. 一个问题只收到一条最终回复。专家晚到时，明确标为“补充更新”。
3. 数字照原样展示，不改写。
4. 说不清楚时，问用户，不猜。

## 指标建议

| 指标 | 含义 |
|---|---|
| 各层命中率（L0/L1/L2） | 确定性路径占比越高，成本与延迟越低 |
| 澄清率 | 过高说明术语树或意图描述需要补充 |
| 守卫触发率与拒答率 | 过高说明规则过严或上游数据有问题 |
| 草稿超时发送率 | 反映外部专家的可用性 |
| 补充更新率 | 反映草稿超时设置是否合理 |
| 数字守卫丢弃率 | 反映 L2 提示词与模型的稳定性 |

## 不在范围内

多轮对话记忆、真实的专家 Agent、持久化队列、权限体系；本仓库 demo 只保留关键词检索，向量索引、BM25、RRF、重排与多跳均未实现，仅作链路设计。
这些是接入真实系统时需要补的部分，本项目只展示分层与兜底的结构。
